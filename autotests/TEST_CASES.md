# Тест-кейсы

Один набор сценариев реализован на нескольких языках. Номер кейса (TC-API-xx, UI-xx) одинаковый
во всех реализациях — по нему удобно сверять отчёты и заводить кейсы в Allure TestOps.

## Версия для телефона (GitHub Pages, без сервера)

Сайт `frontend/out` после `npm run build:pages`: запросы `/api/*` перехватывает service worker и передаёт
«серверу» в Web Worker (`frontend/lib/local`), портреты хранятся в IndexedDB браузера. Сквозные тесты —
`frontend/tests/pages` (`npx playwright test -c playwright.pages.config.ts`, телефон Pixel 7), юнит-тесты —
`tests/unit/local-core.test.ts` (совпадение расчёта с Python по эталону `tests/fixtures/parity.json.gz`) и
`tests/unit/local-server.test.ts` (все адреса API: портрет, нити, учёт времени, файл проекта, ошибки).

| № | Сценарий |

| PH-01 | Фото → «Сделать портрет» прямо в телефоне → студия с рекомендованным числом линий; кнопок PDF и шаблона нет; плетение: шаг вперёд |
| PH-02 | Редактор объясняет, что поиска лица и удаления фона в телефоне нет (это умеет программа на компьютере) |

## Покрытие кода

* Бэкенд (pytest, `pytest --cov=app --cov-branch`): **97 %** строк и ветвлений. Не покрыты только аварийные
  ветки, которые нельзя вызвать без порчи окружения (например, ответ модели из одних нулей).
* Фронтенд, юнит-тесты (`npm run test:coverage`): **≈65 %** логики, хуков и компонентов. Остальное — страницы,
  запись видео, загрузка фото — проверяют сценарии Playwright UI-01…UI-32 в настоящем браузере.
* Крайние случаи без своего номера (запасной поиск лица, обрыв скачивания модели, лимиты API) — в
  `backend/tests/test_edge_cases.py` и `frontend/tests/unit/edge.test.tsx`.
