# Нитеграф — портрет из нитей

Загружаете фото — получаете круглую картину из чёрной лески на 240 гвоздях и пошаговую инструкцию,
как её натянуть.

**Установка, получение обновлений и запуск — в [docs/INSTALL.md](docs/INSTALL.md).**
Коротко: `git clone https://github.com/alzhelez/string_art.git`, затем `./scripts/start.sh`
(macOS/Linux) или `scripts\start.bat` (Windows) и откройте http://localhost:3000.

## Что умеет

- **Гвозди.** Круг делится осями X и Y на 4 сектора: **A** — слева сверху, **B** — справа сверху,
  **C** — справа снизу, **D** — слева снизу. В каждом секторе 60 равноудалённых гвоздей, нумерация по
  часовой стрелке. A1 — первый гвоздь над левой точкой оси X, A60 — у верхней точки.
- **Подготовка фото.** Кадр выбирается прямо в круге: перетащить, колесо мыши или два пальца — масштаб.
  Яркость и контраст. Дополнительно: **«Выделить лицо»** (кадр встаёт на лицо, алгоритм прорабатывает
  его детальнее) и **«Убрать фон»** (фон становится белым, все линии уходят на человека).
  **«Автонастройка»** одной кнопкой: находит лицо, по возможности убирает фон и перебирает яркость и
  контраст, пока картина из лески не станет максимально похожей на фото.
  Фото готового портрета можно поправить позже — схема пересчитается.
- **Размер.** Диаметр круга 30 / 40 / 50 / 60 / 70 см или своё значение 20–150 см.
- **Линии.** 1000–5000, ползунок с мгновенным превью. Рекомендация — количество, при котором картина
  **больше всего похожа на исходное фото** (с учётом диаметра и толщины лески); рядом — график сходства.
- **Леска.** Точная длина всех отрезков + запас 15 % и минимальная стандартная катушка
  (100 / 150 / 200 / 300 / 500 / 1000 / 1500 / 2000 / 3000 / 5000 м, дальше — несколько по 1000 м).
- **Пошаговый режим.** Шаг вида **A12 → C37**, автоперелистывание (по умолчанию 2,0 с, кнопки ±0,1 с),
  переход к шагу по номеру, клавиши. Шаг и скорость сохраняются автоматически.
- **Звук шага**: короткий сигнал, голос на русском или тишина. А пока руки заняты леской — **фильм или
  музыка**: файлы с компьютера, YouTube, RuTube, прямые ссылки на mp3/mp4 и интернет-радио, плейлист,
  «картинка в картинке». Видео встаёт на паузу вместе с плетением и продолжается вместе с ним.
- **Светлая и тёмная тема**, удобно и на телефоне.
- **PDF-инструкция**: обложка с картиной и расчётом, схема гвоздей, все шаги с чекбоксами для печати.
- **Несколько проектов** с прогрессом на карточках.

Как считается портрет, как мерили точность и что пробовали — [docs/ALGORITHM.md](docs/ALGORITHM.md).

## Структура

```
backend/            Python 3.11+, FastAPI, NumPy, Pillow, OpenCV, ReportLab, SQLite
  app/
    algorithm.py    жадный алгоритм string art (+ карта важности для лица)
    photo.py        подготовка фото: кадр, тона, лицо, фон
    geometry.py     гвозди, сектора, хорды
    thread.py       длина лески и подбор катушки
    pdf.py          PDF-инструкция
    main.py         HTTP API (документация: http://localhost:8000/docs)
  requirements-bg.txt  необязательное удаление фона (rembg)
  tests/            pytest: юнит + API
frontend/           Next.js 16 + React 19 + TypeScript
  app/              страницы: список, студия, редактор фото, плетение
  components/       Board (canvas), PhotoEditor, WeavePlayer, DiameterPicker…
  lib/prep.ts       та же подготовка фото, что на бэкенде, — для живого превью
  tests/unit/       Vitest + Testing Library
  tests/e2e/        Playwright: UI (десктоп + мобильный) и API-контракт
autotests/
  TEST_CASES.md     единый список кейсов TC-API-xx / UI-xx
  fixtures/         общие тестовые картинки и эталон подготовки фото
  java/             TestNG + RestAssured + AssertJ + Allure + PDFBox (Maven)
  go/               стандартный testing + net/http
  ruby/             Minitest + Net::HTTP
  csharp/           xUnit + HttpClient (.NET 8)
scripts/            start.sh / start.bat — запуск одной командой
docs/               установка и обновление, описание алгоритма
.github/workflows/  автотесты на GitHub Actions при каждом push
.gitlab-ci.yml      то же для GitLab CI
```

## Тесты

| Набор | Команда | Где запускать |
|-------|---------|---------------|
| Python: юнит + API | `cd backend && python -m pytest` | ничего поднимать не нужно |
| TypeScript: юнит + компоненты | `cd frontend && npm test` | ничего поднимать не нужно |
| TypeScript: E2E UI + API (Playwright) | `cd frontend && npx playwright install chromium && npm run test:e2e` | сам поднимает бэкенд на 8001 и фронт на 3001 с временной БД |
| Java (TestNG + RestAssured + Allure) | `cd autotests/java && mvn test` → `mvn allure:serve` | нужен запущенный бэкенд на 8000 |
| Go | `cd autotests/go && go test -v ./...` | нужен бэкенд на 8000 |
| Ruby | `ruby autotests/ruby/api_test.rb` | нужен бэкенд на 8000 |
| C# | `cd autotests/csharp && dotnet test` | нужен бэкенд на 8000 |

Адрес бэкенда для API-наборов: `-Dapi.baseUrl=…` (Java) или переменная `STRINGART_API` (Go, Ruby, C#).
Все языковые наборы создают свои проекты и удаляют их за собой.
